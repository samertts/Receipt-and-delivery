# تقرير التدقيق الأمني والتقني

**تاريخ التدقيق:** 2026-08-26

**النطاق:** Backend/FastAPI، واجهة Vue/Vite، تطبيق PySide6، الجسر المحلي للأجهزة، التخزين المحلي، الاعتماديات، Docker وGitHub Actions.

> هذا التدقيق ساكن وديناميكي محدود داخل بيئة الاختبار المحلية. لم تُنفذ محاولات اختراق ضد خوادم خارجية أو حسابات حقيقية، ولا يمثل التقرير اختبار اختراق كاملًا أو شهادة امتثال.

## الملخص التنفيذي

كشفت المراجعة عن نقاط ضعف عملية في رفع الملفات، مصادقة WebSocket، كشف تفاصيل health، تخزين مفتاح التطوير، محدد المعدل، وتشغيل الحاويات وسير الإصدار. عولجت النقاط القابلة للإصلاح في نفس دورة العمل، وأضيفت اختبارات تمنع عودة أهم العيوب. لم تُظهر `pip-audit` أو `npm audit --audit-level=high` ثغرات معروفة في الاعتماديات الحالية، كما لم تُظهر Bandit نتائج متوسطة أو عالية بعد الإصلاحات.

## النتائج والإجراءات

| المعرف | الخطورة | الحالة | النتيجة |
|---|---|---|---|
| SEC-01 | عالية | عولجت | كان JWT يمرر في query string لقناة WebSocket، مما قد يعرضه في سجلات proxy أو أدوات التشخيص. أصبحت المصادقة برسالة أولى داخل القناة، مع مهلة وحجم محدودين وحد أقصى للاتصالات لكل مستخدم. |
| SEC-02 | متوسطة/عالية | عولجت | رفع المرفقات كان يقرأ الملف كاملًا في الذاكرة، وكان يستخدم `hashlib` دون import، مع احتمال ملفات orphan بعد فشل قاعدة البيانات. أصبح الرفع متدفقًا إلى ملف مؤقت، مع حد حجم، تحقق magic bytes، إعادة تسمية ذرية، وتنظيف عند الفشل. |
| SEC-03 | متوسطة | عولجت | فحص مسار تنزيل المرفق باستخدام `startswith` ليس ضمانًا صحيحًا لحدود المسار. أصبح التحقق باستخدام `Path.is_relative_to`، وأصبح مجلد التخزين مطلقًا ومحددًا من الإعدادات. |
| SEC-04 | متوسطة | عولجت | health وreadiness كانا يعيدان نص استثناء قاعدة البيانات الخام. أصبحت الاستجابة عامة، مع تسجيل التفاصيل داخليًا وإغلاق جلسة DB في `finally`. |
| SEC-05 | متوسطة | عولجت | محدد Redis كان يستخدم timestamp كـ member، فيدمج الطلبات داخل الثانية نفسها ويقلل العد الفعلي. أصبح لكل طلب member عشوائي فريد، وأصبح محدد الذاكرة thread-safe. |
| SEC-06 | متوسطة | عولجت | كان مفتاح التطوير التلقائي يُحفظ داخل شجرة Backend بصلاحيات افتراضية. أصبح المسار الافتراضي خارج المشروع وبصلاحيات `600`، مع رفض تشغيل الإنتاج بالمفتاح التلقائي. |
| SEC-07 | متوسطة | عولجت | إعدادات الإنتاج كانت تقبل معلومات PostgreSQL الافتراضية وCORS غير المشفر. أصبح التشغيل الإنتاجي يرفض بيانات DB الافتراضية وOrigins غير HTTPS أو wildcard. |

| SEC-09 | منخفضة/متوسطة | عولجت | updater كان يتحقق من بداية النص `https://` فقط. أصبح يتحقق من scheme وnetloc ومن scheme النهائي بعد إعادة التوجيه. |
| SEC-10 | منخفضة | عولجت | Compose التطويري كان ينشر PostgreSQL وBackend وFrontend على جميع واجهات الشبكة، وكان يملك fallback لكلمة مرور معروفة. قُيدت المنافذ إلى localhost وأزيل fallback. |

## مخاطر متبقية وتوصيات إلزامية قبل الإنتاج

لا يزال access وrefresh token في تطبيق الويب تحت إدارة JavaScript داخل الذاكرة، وليس في Cookie من نوع HttpOnly/Secure/SameSite. هذا يقلل بقاء الرمز بعد إعادة تحميل الصفحة، لكنه لا يمنع سرقته إذا حدث XSS أثناء الجلسة. ينبغي في مرحلة لاحقة نقل جلسة الويب إلى Cookie محمية مع CSRF protection، أو اعتماد BFF، بعد تصميم migration واختبارات تكامل كاملة.

ما زال توثيق OpenAPI وواجهات health وversion متاحًا دون مصادقة. لا يظهر منها سر أو بيانات معاملة بعد الإصلاح، لكنها تزيد سطح الاستطلاع. يوصى بتعطيل docs في الإنتاج أو حمايتها، وقصر health التفصيلي على شبكة المراقبة، مع إبقاء liveness العام عند الحاجة.

حاوية Backend أصبحت تعمل كمستخدم غير root، لكن Compose الإنتاجي يعرض Frontend على HTTP/80 فقط ويعتمد على TLS reverse proxy خارجي. يجب نشر TLS فعليًا قبل تعريض الخدمة للإنترنت، وتحديد `FORWARDED_ALLOW_IPS` على عنوان الوكيل الموثوق بدل استخدام wildcard. يجب أيضًا وضع حد طلبات على مستوى proxy وWAF، لأن محدد التطبيق وحده ليس كافيًا ضد DoS موزع.

الجسر المحلي مضبوط افتراضيًا على `127.0.0.1` ويتطلب `X-Device-Bridge-Token` للأوامر، لكن تغييره إلى `0.0.0.0` أو تعريضه للشبكة يحوله إلى سطح هجوم مباشر. يجب إبقاؤه محليًا أو وضع TLS ومصادقة شبكة وحدود معدل عند الحاجة، وعدم استخدام token ضعيف أو مشارك بين أجهزة متعددة.

صلاحيات RBAC الحالية على مستوى الدور وليست دائمًا على مستوى مالك المعاملة أو المؤسسة. هذا مناسب للتشغيل المركزي إذا كان مقصودًا، لكنه لا يحقق عزلًا بين فروع أو مؤسسات متعددة. إذا كان النظام سيخدم جهات مستقلة، يجب إضافة tenant/organization scoping إلى كل استعلام حساس واختبار عدم الوصول العرضي.

## فحوصات منفذة

شُغلت فحوصات Bandit على Backend وتطبيق سطح المكتب، و`pip-audit -r requirements.txt`، و`npm audit --audit-level=high`، وRuff. كما شُغلت اختبارات المرفقات وhealth وWebSocket وRBAC والمصادقة، إضافة إلى اختبارات المشروع السابقة. فشل أي فحص أمني أو lint في Workflow يمنع بناء ونشر الإصدار.

## حدود التدقيق

لم يشمل التدقيق فحصًا خارجيًا على بيئة إنتاج، أو اختبار اختراق موزع، أو مراجعة إعدادات DNS وTLS الفعلية، أو تحليل ملفات المستخدم الموجودة خارج المستودع، أو اختبار طابعات فعلية. يجب إعادة التدقيق بعد إعداد الإنتاج، وبعد أي تغيير في المصادقة أو الجسر المحلي أو آلية التحديث.
