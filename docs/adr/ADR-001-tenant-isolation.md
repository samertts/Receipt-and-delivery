# ADR-001: عزل المؤسسات قبل تفعيل multi-facility

**الحالة:** مقبول كقرار تخطيط
**التاريخ:** 26 أغسطس 2026

## السياق

يحتوي Backend على مستخدمين وأدوار RBAC، لكن نموذج User لا يفرض tenant أو organization scope شاملًا على المعاملات والمرفقات وسجلات التدقيق والمزامنة. لذلك لا يمكن اعتبار مرشح `institution_id` في بعض المسارات عزلًا كافيًا؛ قد تبقى استعلامات أو تقارير أو WebSocket خارج النطاق.

## القرار

لا يُفعّل النظام كمنصة متعددة المؤسسات قبل إضافة tenant boundary صريحة إلى النموذج وسياسة الاستعلام. يجب أن تشمل migration وbackfill وforeign keys وunique constraints المناسبة، وربط المستخدم بالمؤسسة أو مجموعة المؤسسات، وإضافة authorization dependency مركزية، واختبارات سلبية تثبت عدم قراءة أو تعديل أو تصدير بيانات مؤسسة أخرى.

## تبعات القرار

هذا يؤجل ادعاء multi-facility production-ready، لكنه يمنع حلًا تجميليًا يعطي إحساسًا زائفًا بالعزل. يبقى RBAC الحالي صالحًا للتشغيل المركزي المقصود فقط، مع ضرورة ضبط المؤسسة المستهدفة تشغيليًا وعدم تعريض `/api/v1` لعملاء browser. بعد تنفيذ migration يجب تحديث التقارير والمرفقات والمزامنة والإشعارات وaudit logs مع نفس policy.

## معايير القبول المستقبلية

لا يُغلق القرار إلا بعد مراجعة كل route وrepository حساس، واختبارات cross-tenant على read/write/delete/export/sync، ومراجعة schema في PostgreSQL staging، وقياس أثر الفهارس الجديدة. لا تُستخدم بيانات مرضى حقيقية في هذه الاختبارات.
