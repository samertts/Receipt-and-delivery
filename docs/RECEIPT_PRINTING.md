# طباعة الوصل والإيصال

## المسار الموصى به

يوفر النظام مسارين للطباعة. في تطبيق Windows المكتبي افتح تفاصيل المعاملة ثم اضغط **طباعة**. يولد التطبيق ملف PDF رسميًا ويفتحه في عارض PDF الافتراضي، ومنه اختر الطابعة أو خيار **Save as PDF**. في واجهة الويب افتح **تفاصيل المعاملة** ثم اضغط **طباعة الوصل**؛ ستفتح نافذة معاينة الطباعة، وبعدها اختر الطابعة أو الحفظ بصيغة PDF.

لا تتم الطباعة بصمت أو دون موافقة المستخدم. هذا يمنع إرسال وصل خاطئ إلى طابعة مشتركة، ويسمح للمستخدم بتحديد حجم الورق والطابعة وعدد النسخ.

## محتويات الوصل

| الجزء | المحتوى |
|---|---|
| الرأس | اسم نظام إدارة الاستلام المختبري وعبارة إيصال رسمي. |
| تعريف الوصل | رقم الوصل، نوع المعاملة، الجهة، التاريخ، والحالة. |
| الأطراف | الجهة المرسلة والمستقبلة، اسم المرسل، واسم المستلم. |
| المرجع | رقم التفويض وتاريخ التفويض عند توفرهما. |
| جدول العينات | نوع العينة، الإجمالي، الصالح، التالف، المرفوض، غير المطابق، وحالة النقل، مع صف إجمالي. |
| الملاحظات | الملاحظات ومعلومات النقل والتعليقات الإضافية عند وجودها. |
| التحقق | QR Code يحتوي بيانات تعريف الوصل، وCode128 لرقم الوصل لقراءته بقارئ باركود. |
| التوقيع | خانة توقيع المرسل وخانة توقيع المستلم. |
| التذييل | إصدار التطبيق وسنة التوليد. |

## شكل الملف

ينتج تطبيق Windows ملف **A4 PDF** بتخطيط عربي من اليمين إلى اليسار، مع دعم العربية والإنجليزية والأرقام. يتم إصلاح تشكيل واتجاه النص العربي قبل إدخاله في ReportLab حتى لا تظهر الحروف معكوسة. يدعم القالب جدولًا متعدد الصفوف، ويكرر صف العناوين عند امتداد الوصل إلى صفحة أخرى.

يُحفظ الملف المكتبي داخل مجلد بيانات التطبيق، عادةً:

```text
%LOCALAPPDATA%\\LabReceiptSystem\\receipts\\<receipt_no>.pdf
```

قد يختلف المسار في وضع التطوير أو حسب إعدادات `STORAGE_DIR`. لا يحتوي QR Code على صورة أو ملف مرفق؛ هو معرف نصي للوصل يمكن توسيعه لاحقًا إلى رابط تحقق داخلي إذا تم إنشاء خدمة تحقق.

## الطباعة من الويب

الطباعة من الويب تستخدم نافذة معاينة المتصفح، لذلك تحتاج إلى السماح بالنوافذ المنبثقة إذا منعها المتصفح. اختر **Print** من المعاينة، ثم حدد الطابعة أو **Save to PDF**. في الشاشات الصغيرة يستخدم قالبًا بعمود واحد للبيانات ويُبقي الجدول قابلًا للقراءة قدر الإمكان.

زر **طباعة اختبار** في مركز الأجهزة مخصص لفحص الطابعة والنوافذ المنبثقة، وليس بديلًا عن زر **طباعة الوصل** الموجود في تفاصيل المعاملة.

## الطابعات المتخصصة

الطباعة العادية تمر عبر عارض PDF أو معاينة المتصفح وتعمل مع الطابعات التي يتعرف عليها نظام التشغيل. أما الطباعة الحرارية الخام أو أوامر ESC/POS أو طابعات USB/Serial المتخصصة فتحتاج إلى الجسر المحلي الاختياري الموثق في [`DEVICE_INTEGRATION.md`](../DEVICE_INTEGRATION.md). لا ينبغي فتح منفذ طباعة خام غير مصادق عليه على الشبكة.

## نموذج تجريبي

يوجد نموذج PDF ببيانات وهمية في [`sample_receipt.pdf`](sample_receipt.pdf). لا تستخدم بياناته في التشغيل الفعلي؛ الغرض منه معاينة ترتيب الرأس والحقول والجدول وQR/Barcode والتوقيعات.

## التخصيص والتخطيطات الجديدة

يمكن للمستخدم الذي يملك صلاحية تحديث الإعدادات فتح **إعدادات النظام → هوية الإيصال** في تطبيق سطح المكتب. تُحفظ الإعدادات محليًا داخل ملف JSON في مجلد بيانات التطبيق، وتشمل اسم الشركة والعنوان الفرعي والتذييل واللون الرئيسي ومسار شعار محلي بصيغة PNG أو JPEG والتخطيط الافتراضي. يتحقق التطبيق من امتداد الصورة ووجودها وحجمها قبل الحفظ، ويكتب الملف بطريقة ذرية، ولا يرفع الشعار أو بيانات المعاملة إلى خدمة خارجية.

| التخطيط | النتيجة | الاستخدام المقترح |
|---|---|---|
| `a4` | إيصال واحد بحجم A4 عمودي | الأرشفة الرسمية والملفات الكبيرة |
| `a5` | إيصال واحد بحجم A5 عمودي | التسليم اليومي والاستهلاك الأقل للورق |
| `a4-two-up` | نسختان متطابقتان بحجم A5 جنبًا إلى جنب على ورقة A4 أفقية | نسخة للمستلم ونسخة للمرسل |

في التخطيط الثنائي تُضاف تسمية واضحة **نسخة المستلم** و**نسخة المرسل**، ويجري إنشاء الملفات الوسيطة داخل مجلد مؤقت ثم حذفها بعد الدمج. يظل الملف النهائي هو القرار الذي يفتحه المستخدم، ولا يرسل التطبيق أمر طباعة صامتًا.

## التاريخ والوقت

يعرض الوصل تاريخ المعاملة، ووقت المعاملة عند توفره، ووقت التسجيل، وآخر تحديث. تُنسّق قيم ISO أو قيم `datetime` إلى الصيغة `YYYY-MM-DD HH:MM:SS`. إذا لم تُحفظ منطقة زمنية مع القيمة، لا يخترع التطبيق منطقة زمنية ولا ينسب الوقت إلى منطقة غير مؤكدة؛ بل يعرض القيمة المنسقة فقط.

## طباعة الويب

تدعم صفحة تفاصيل المعاملة في الويب اختيار التخطيط نفسه عبر CSS للطباعة. يحدد التطبيق حجم صفحة `@page` وفق الاختيار، ويعرض التخطيط الثنائي داخل صفحة A4 أفقية مع نسختي المستلم والمرسل. يجب اعتبار هذه معاينة متصفح؛ أما دمج PDF المكتبي فهو المسار الأكثر ثباتًا للأرشفة. في جميع الأحوال يبقى اختيار الطابعة والحفظ PDF بيد المستخدم.

## رسائل الأخطاء

لا تعرض واجهة سطح المكتب نصوص الاستثناءات الخام، لأن ذلك قد يكشف مسارات أو معلومات عن قاعدة البيانات. يسجل التطبيق التفاصيل التقنية داخليًا للمراجعة، ثم يعرض رسالة عربية عامة بحسب نوع المشكلة مثل الصلاحيات، الملف المفقود، قاعدة البيانات المشغولة، الشبكة، أو الطباعة.

يُفضّل عند تعذر فتح ملف أو طباعة إيصال مراجعة سجل التطبيق بعد معالجة الرسالة العربية، والتحقق من صلاحية مجلد بيانات التطبيق واتصال الطابعة. لا تُضمّن في رسائل المستخدم بيانات عينات أو رموز وصول أو مسارات سرية.
