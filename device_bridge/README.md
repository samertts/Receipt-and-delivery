# Optional local device bridge

هذا البرنامج اختياري. استخدمه فقط على الكمبيوتر الذي تتصل به الطابعة، ولا حاجة إليه للكاميرا أو قارئ الباركود بنمط لوحة المفاتيح أو OCR أو الطباعة العادية من المتصفح.

## التشغيل

من مجلد `device_bridge` ثبّت المتطلبات ثم أنشئ رمزًا عشوائيًا طويلًا:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
export DEVICE_BRIDGE_TOKEN="ضع-رمزًا-عشوائيًا-طويلًا-هنا"
export BRIDGE_ALLOWED_ORIGINS="https://lab.example.com,http://localhost:5173"
python app.py
```

يستمع الجسر افتراضيًا على `127.0.0.1:17321` فقط. يمكن تغيير المنفذ عبر `BRIDGE_PORT`، لكن لا تغيّر `BRIDGE_HOST` إلى عنوان شبكة عامة. يجب تشغيل CUPS وأدوات `lpstat` و`lp` على نظام التشغيل حتى تظهر الطابعات.

## العقد المتاح

| المسار | الحماية | الوظيفة |
|---|---|---|
| `GET /health` | لا يتطلب رمزًا | فحص محلي بسيط لا يعرض قائمة الطابعات أو الرمز. |
| `GET /printers` | `X-Device-Bridge-Token` | عرض أسماء الطابعات التي يكتشفها CUPS. |
| `POST /print` | `X-Device-Bridge-Token` | طباعة نص صريح عبر `lp` بعد التحقق من اسم الطابعة. |

مثال طلب طباعة:

```bash
curl -H "X-Device-Bridge-Token: $DEVICE_BRIDGE_TOKEN" \\
  -H "Content-Type: application/json" \\
  -d '{"content":"Receipt and delivery test\n","content_type":"text"}' \\
  http://127.0.0.1:17321/print
```

لا يقبل الجسر HTML أو أوامر ESC/POS الخام، ولا ينفذ أوامر shell مركبة؛ تُمرَّر الوسائط إلى `subprocess` كقائمة، ويُتحقق من اسم الطابعة، ويُحذف الملف المؤقت بعد إرسال المهمة. قبل ربط الواجهة بهذا العقد، أضف تخزينًا آمنًا لرمز الاقتران في الجهاز وواجهة اختيار طابعة واضحة للمستخدم.

## ملاحظات نشر

الجسر ليس خدمة مستضافة ولا يحل محل خادم التطبيق؛ يجب أن يعمل محليًا وبقاء كمبيوتر الطابعة قيد التشغيل. في بيئة حساسة، احصر Origins على عنوان الواجهة الفعلي، ودوّر الرمز عند تغيير المستخدمين، ولا تفتح المنفذ في جدار الحماية أو الراوتر. اختبره أولًا على طابعة اختبار لأن سلوك تعريفات CUPS يختلف بين الأنظمة.
